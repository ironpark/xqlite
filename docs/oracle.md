## 켜는 법

| 어디서 | 방법 |
| --- | --- |
| SQL | `PRAGMA xq_dialect = 'oracle'` |
| 셸 | `.dialect oracle` |
| Zig API | `.dialect = .oracle` |

```sql
PRAGMA xq_dialect = 'oracle';
CREATE TABLE emp (
  id     NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name   VARCHAR2(40) NOT NULL,
  salary NUMBER(8,2),
  hired  DATE DEFAULT SYSDATE
);
INSERT INTO emp (name, salary) VALUES ('ann', 1000);
COMMIT;                                   -- DML은 트랜잭션을 엽니다
SELECT name, TO_CHAR(hired, 'YYYY-MM-DD') FROM emp WHERE ROWNUM <= 10;
SELECT column_name, data_type FROM user_tab_columns WHERE table_name = 'EMP';
PRAGMA xq_dialect = 'sqlite';             -- PRAGMA는 SQLite 문법 그대로 통과
```

## 구조

프론트엔드는 `src/dialect/oracle/`에 있습니다. 문장을 구문 트리 IR(`src/ir/tree.zig`)로 파싱하고, 내림·렌더링·카탈로그 기록은 공용 `src/ir/lower.zig`와 `render.zig`가 합니다.

| 파일 | 내용 |
| --- | --- |
| `frontend.zig` | 진입점. 한 문장을 파싱해 IR로 내림. MERGE·INSERT ALL은 여러 문장을 한 프로그램으로 내림. 암묵적 트랜잭션, DDL 검사, 오류의 ORA- 코드 |
| `lexer.zig` | Oracle 어휘(아래 [어휘](#어휘)) |
| `parser.zig` | 질의와 식. Oracle 의미를 해석함(`''`, `\|\|`, `ROWNUM`, `(+)`, `DUAL`, 함수 이름과 특수 문법, 결과 열 이름, NULL 정렬, 데이터 사전 뷰) |
| `stmt.zig` | 문장: DML(저장 변환 `xq_ora_coerce()`), MERGE·INSERT ALL, DDL과 타입·검사·identity, 트랜잭션 |
| `dates.zig` | 날짜 연산(`d + 1`, `d1 - d2`)과 숫자 열과 비교하는 문자열 상수 |
| `types.zig` | 타입 → STRICT 저장 타입·검사·카탈로그 철자 |
| `datetime.zig` | 날짜 텍스트, 달력 계산, 날짜 형식 모델(`TO_CHAR`, `TO_DATE`) |

| `test.zig` | 종단 테스트 |

## 빈 문자열은 NULL

Oracle에서 `''`는 NULL입니다. 그래서 `'' IS NULL`은 참, `LENGTH('')`는 NULL, `'a' || NULL`은 `'a'`입니다. 이 방언은 이 규칙을 의미 노드로 일관되게 지킵니다.

| 어디서 | 하는 일 | IR |
| --- | --- | --- |
| 문자열 상수 | `''`는 NULL 상수 | `null` (render는 `NULL`을 씀, `''`가 아님) |
| `\|\|`, `CONCAT(a, b)` | NULL은 건너뛰고, 결과가 `''`이면 NULL | `nullif(concat{skip}(a, b, ...), '')` |
| 문자열 함수 | 인자의 `''`는 NULL, 결과가 `''`이면 NULL(`SUBSTR('abc', 4)`, `REPLACE('aa', 'a')`, `TRIM('  ')`, `LPAD('x', 0)`) | 방언 함수(`xq_oracle_substr` ...), `UPPER`/`LOWER`는 `nullif(upper(x), '')` |
| 저장 | INSERT·UPDATE·MERGE가 Oracle이 만든 테이블의 열에 넣는 값은 `xq_ora_coerce()`를 거침: `''`는 NULL(바인딩한 `''`도) | `func` 노드(엔진 함수) |

`xq_ora_coerce(value, 'TYPE', 'T', 'COL', flags)`는 저장 변환도 함께 합니다.

- 숫자 열: 문자열은 숫자로(`'12.5'` → 12.5, 아니면 `ORA-01722`), `NUMBER(p,s)`는 s자리로 반올림, 정밀도를 넘으면 `ORA-01438`. 정수 값의 실수는 정수로 저장
- 문자 열: 숫자는 Oracle 철자의 텍스트로(0.5 → `'.5'`), 길이를 넘으면 `ORA-12899`, `CHAR(n)`은 공백으로 채움
- 날짜 열: 텍스트를 `YYYY-MM-DD HH24:MI:SS`(`TIMESTAMP`는 소수 6자리)로 바꿈, 아니면 `ORA-01861`
- `RAW`/`BLOB`: 텍스트는 16진수로 읽음, `BOOLEAN`: `TRUE`/`'Y'`/`1` 같은 철자를 1/0으로
- NOT NULL 열(키 포함)에 NULL이나 `''`를 넣으면 `ORA-01400`

한계는 다음과 같습니다.

- `xq_ora_coerce()`는 xq_catalog에 선언 타입이 있는 테이블(이 방언이 만든 테이블)에만 붙습니다. SQLite나 다른 방언이 만든 테이블에는 `''`가 그대로 들어갑니다.
- 다른 방언이나 sqlite3가 쓴 `''` 값은 저장된 그대로 `''`입니다. 이 방언의 함수는 그런 값도 NULL로 읽지만, `col IS NULL`이나 `count(col)`은 `''`를 NULL로 보지 않습니다.
- `(a, b) = (SELECT ...)` 꼴의 UPDATE SET 값은 변환하지 않습니다.
- `||`의 숫자 피연산자는 SQLite가 텍스트로 바꿉니다(`'x' || 0.5`는 `'x0.5'`, Oracle은 `'x.5'`).

## 이름의 대소문자

- 따옴표 없는 식별자는 대문자로 접고(`emp` → `EMP`), `"Quoted"`는 그대로 둡니다. 그래서 이 방언이 만든 테이블과 열의 이름은 `sqlite_schema`에 대문자로 남고, `USER_TABLES.TABLE_NAME`도 Oracle처럼 `EMP`입니다.
- SQLite의 이름 비교는 대소문자를 구분하지 않습니다. 그래서 `"Emp"`와 `EMP`는 Oracle에서는 다른 테이블이지만 xqlite에서는 같은 테이블입니다. 반대로 SQLite에서 `emp`로 만든 테이블도 이 방언에서 `EMP`, `emp`, `"emp"`로 모두 찾습니다.
- 결과 열 이름은 Oracle 규칙을 따릅니다. 열이면 그 열 이름(만든 대로의 대소문자), 의사 열이면 `NEXTVAL`, `ROWID`, 그 밖의 식이면 식의 텍스트를 대문자로 바꾸고 공백을 뺀 것(`count(*)` → `COUNT(*)`, `NVL(b, 'x')` → `NVL(B,'X')`)입니다.
- 스키마(사용자) 이름도 같은 규칙으로 접습니다(`hr.emp`는 사용자 `HR`의 `EMP`). 스키마는 [사용자와 스키마](#사용자와-스키마)를 보세요.

## 지원 범위

### 어휘

- 문자열: `'...'`(`''`로 따옴표), `N'...'`, 대체 따옴표 `q'[...]'`(`{}` `()` `<>` 또는 같은 문자 쌍, `Q`/`nq`도)
- 바인드 변수: `:name`은 SQLite의 이름 있는 매개변수 `:name`(`sqlite3_bind_parameter_index(":name")`), `:1`은 번호 매개변수 `?1`. 한 문장에서 둘을 섞으면 `:1`과 첫 이름이 같은 번호가 됩니다.
- 숫자: `42`, `4.2`, `.5`, `1e10`, `1.5f`/`2d`(접미사 무시)
- 주석: `--`, `/* */`(중첩 없음). 힌트 `/*+ ... */`는 주석입니다.
- 문장 끝: `;`, 그리고 SQL*Plus 스크립트처럼 홀로 있는 줄의 `/`
- 연산자: `||`, `<>`/`!=`/`^=`/`~=`, `(+)`

### SELECT

| 영역 | 지원 |
| --- | --- |
| 기본 | `DISTINCT`/`UNIQUE`, `WHERE`, `GROUP BY`, `HAVING`, `WINDOW` |
| FROM | 테이블, 서브쿼리, `DUAL`(없는 테이블로 다룸, `SELECT *`이면 `DUMMY` 열 하나), 테이블 함수 |
| JOIN | ANSI `INNER`/`LEFT`/`RIGHT`/`FULL`/`CROSS`/`NATURAL`, `ON`/`USING`, 옛 `(+)` 외부 조인 |
| 정렬 | `ORDER BY ... [ASC\|DESC] [NULLS FIRST\|LAST]`(기본은 NULL이 가장 큰 값) |
| 행 수 제한 | `WHERE ROWNUM <= n`(`<`, `= 1`, `BETWEEN 1 AND n`) → LIMIT, `OFFSET n ROWS`, `FETCH FIRST\|NEXT n ROWS ONLY` |
| 집합 연산 | `UNION [ALL]`/`INTERSECT`/`MINUS`(같은 우선순위, 왼쪽부터) |
| CTE | `WITH`, `RECURSIVE` 없는 재귀 CTE(열 목록과 함께) |
| 그 밖 | 스칼라·상관 서브쿼리, `IN`/`EXISTS`/`= ANY (...)`/`<> ALL (...)`, 행 값, `FOR UPDATE`(무시) |

`ROWNUM`의 규칙은 다음과 같습니다.

- WHERE의 `ROWNUM` 조건은 그 질의의 LIMIT이 됩니다. Oracle은 정렬·그룹 전에 번호를 매기므로, 같은 질의에 `ORDER BY`가 있으면 `SELECT * FROM (... LIMIT n) ORDER BY ...`로, 집계·`GROUP BY`·`DISTINCT`가 있으면 FROM 항목(하나일 때만)을 `(SELECT * FROM t WHERE ... LIMIT n) t`로 감쌉니다.
- `ROWNUM > n`과 `ROWNUM = n`(n > 1)은 Oracle처럼 아무 행도 내지 않습니다.
- 그 밖의 자리(결과 열, `ORDER BY`)에서는 `row_number() OVER ()`입니다.
- UPDATE·DELETE의 `WHERE ROWNUM <= n`도 LIMIT입니다.

`(+)` 외부 조인은 WHERE의 각 조건에서 `(+)`가 붙은 열의 FROM 항목을 찾아, 그 조건들을 그 항목의 ON으로 옮기고 `LEFT JOIN`으로 만듭니다. `(+)` 쪽이 두 항목 중 첫 번째면 두 번째를 `RIGHT JOIN`으로 만듭니다. ANSI 조인과 섞으면 `ORA-25156`입니다.

### DML

- **INSERT**: 열 목록, `VALUES`(여러 행도), 서브쿼리, `DEFAULT`
- **INSERT ALL / INSERT FIRST**: 무조건 `INTO ...` 여러 개, `WHEN ... THEN INTO ...`, `ELSE INTO ...`
- **UPDATE**: `SET a = ...`, `SET (a, b) = (subquery)`, `= DEFAULT`, `t.a = ...`
- **DELETE**: `FROM` 생략 가능
- **MERGE**: `WHEN MATCHED THEN UPDATE SET ... [WHERE] [DELETE WHERE]`, `WHEN NOT MATCHED THEN INSERT ... VALUES ... [WHERE]`([MERGE와 INSERT ALL](#merge와-insert-all))
- **TRUNCATE TABLE**

### 트랜잭션

`COMMIT [WORK]`, `ROLLBACK [WORK]`, `SAVEPOINT s`, `ROLLBACK TO [SAVEPOINT] s`. `SET TRANSACTION`, `ALTER SESSION`(`SET CURRENT_SCHEMA` 말고), `LOCK TABLE`은 받아들이고 아무것도 하지 않습니다. `EXPLAIN PLAN FOR`는 SQLite의 `EXPLAIN QUERY PLAN` 결과를 냅니다.

### DDL

- **CREATE TABLE**: 열 제약 `[CONSTRAINT n] NOT NULL`/`NULL`/`PRIMARY KEY`/`UNIQUE`/`CHECK`/`REFERENCES t (c) [ON DELETE CASCADE|SET NULL]`, `DEFAULT [ON NULL]`, 테이블 제약, 가상 열 `[GENERATED ALWAYS] AS (...) [VIRTUAL]`, identity `GENERATED {ALWAYS|BY DEFAULT [ON NULL]} AS IDENTITY [(옵션)]`, `CREATE TABLE ... AS SELECT`, `GLOBAL TEMPORARY`, 저장 옵션(`TABLESPACE`, `PCTFREE`, `STORAGE (...)` ...)과 제약 상태(`ENABLE`, `USING INDEX` ...)는 무시. 키 열은 Oracle처럼 NOT NULL입니다.
- **CREATE [UNIQUE|BITMAP] INDEX**, **CREATE [OR REPLACE] [FORCE] VIEW ... [WITH READ ONLY]**
- **CREATE SEQUENCE**: `START WITH`, `INCREMENT BY`, `MINVALUE`, `MAXVALUE`, `CYCLE`/`NOCYCLE`, `CACHE`/`NOCACHE`/`ORDER`(무시)
- **ALTER TABLE**: `ADD (열)`/`ADD 열`, `DROP COLUMN`/`DROP (열)`, `RENAME COLUMN a TO b`, `RENAME TO`. 한 번에 한 열씩입니다.
- **DROP TABLE ... [CASCADE CONSTRAINTS] [PURGE]**, **DROP VIEW/INDEX/SEQUENCE**, 23ai의 `IF [NOT] EXISTS`
- **RENAME a TO b**, **COMMENT ON TABLE/COLUMN ... IS '...'**(카탈로그 키 `oracle.comment`, `USER_TAB_COMMENTS`/`USER_COL_COMMENTS`)

### 식과 연산자

| 영역 | 지원 |
| --- | --- |
| 연산자 우선순위 | `OR` < `AND` < `NOT` < 비교·`IS`·`LIKE`·`BETWEEN`·`IN` < `+ - \|\|` < `* /` < 단항 |
| 나눗셈 | `/`는 실수 나눗셈(`7/2` = 3.5) |
| `LIKE` | 대소문자 구분, `ESCAPE`가 없으면 이스케이프 문자 없음(`xq_like(..., '')`) |
| NULL | `IS [NOT] NULL`, `IS [NOT] TRUE/FALSE`(23ai) |
| `CASE` | 단순·검색 `CASE` |
| `CAST` | `CAST(x AS type)`는 `xq_ora_cast(x, 'TYPE')`(저장 변환과 같은 규칙) |
| 의사 열 | `ROWNUM`, `ROWID`(SQLite의 rowid), `s.NEXTVAL`/`s.CURRVAL`, `SYSDATE`, `SYSTIMESTAMP`, `CURRENT_DATE`/`CURRENT_TIMESTAMP`, `USER`, `UID` |
| 날짜 상수 | `DATE 'YYYY-MM-DD'`, `TIMESTAMP 'YYYY-MM-DD HH24:MI:SS[.f]'` |
| 암묵적 변환 | `NUMBER` 열과 비교하는 문자열 상수(`n = '5'`, `BETWEEN`, `IN`)는 숫자 |

`s.NEXTVAL`은 Oracle처럼 한 행에서 한 번만 늘어납니다. 같은 결과 열 목록, `VALUES` 행, `SET` 목록 안의 두 번째 `NEXTVAL`은 `CURRVAL`입니다. 없는 시퀀스는 컴파일할 때 `ORA-02289`입니다.

### 함수

| 분류 | 함수 |
| --- | --- |
| NULL | `NVL`(→ `coalesce`), `NVL2`, `DECODE`(NULL끼리 같음), `COALESCE`, `NULLIF`, `LNNVL` |
| 문자열 | `SUBSTR`(음수·0 위치), `INSTR`(음수 위치·n번째), `LENGTH`/`LENGTHB`, `UPPER`/`LOWER`/`INITCAP`, `LPAD`/`RPAD`, `TRIM([LEADING\|TRAILING\|BOTH] [c FROM] s)`/`LTRIM`/`RTRIM`(문자 집합), `REPLACE`, `TRANSLATE`, `CONCAT`, `CHR`, `ASCII`, `RAWTOHEX`, `HEXTORAW` |
| 숫자 | `MOD`(`MOD(x, 0)` = x), `ABS`, `CEIL`, `FLOOR`, `ROUND`/`TRUNC`(자릿수), `POWER`, `SQRT`, `SIGN`, `EXP`, `LN`, `LOG(b, x)`, `GREATEST`/`LEAST`(NULL이 있으면 NULL, 첫 인자의 타입으로 비교) |
| 변환 | `TO_CHAR(날짜\|숫자 [, fmt])`, `TO_DATE`, `TO_TIMESTAMP`, `TO_NUMBER(s [, fmt])`, `CAST` |
| 날짜 | `SYSDATE`, `SYSTIMESTAMP`, `ADD_MONTHS`, `MONTHS_BETWEEN`, `LAST_DAY`, `NEXT_DAY`, `TRUNC`/`ROUND(날짜 [, 단위])`, `EXTRACT(YEAR\|MONTH\|DAY\|HOUR\|MINUTE\|SECOND FROM d)` |
| 집계·윈도우 | `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`, `STDDEV`/`VARIANCE`(표본), `LISTAGG(x [, sep]) WITHIN GROUP (ORDER BY ...)`, `ROW_NUMBER`, `RANK`, `DENSE_RANK`, `LAG`, `LEAD`, `FIRST_VALUE`, `NTILE` ... |
| 시퀀스·기타 | `s.NEXTVAL`, `s.CURRVAL`, `SYS_GUID()`(16바이트 난수 blob) |

숫자 형식 모델(`TO_CHAR(n, fmt)`)은 `9`, `0`, `.`/`D`, `,`/`G`, `$`, `S`, `MI`, `PR`, `FM`, `X`를 읽습니다. 자리가 모자라면 `#`입니다. 형식 없는 `TO_CHAR(0.5)`는 Oracle처럼 `.5`입니다.

### 데이터 사전

| 뷰 | 열 |
| --- | --- |
| `USER_TABLES`, `ALL_TABLES` | `TABLE_NAME`, `TABLESPACE_NAME`, `STATUS`, `TEMPORARY` ... (`ALL_*`은 `OWNER`) |
| `USER_TAB_COLUMNS`, `ALL_TAB_COLUMNS` | `COLUMN_NAME`, `DATA_TYPE`, `DATA_LENGTH`, `DATA_PRECISION`, `DATA_SCALE`, `NULLABLE`, `COLUMN_ID`, `DATA_DEFAULT`, `IDENTITY_COLUMN`, `VIRTUAL_COLUMN` |
| `USER_VIEWS`, `ALL_VIEWS` | `VIEW_NAME`, `TEXT_LENGTH`, `TEXT`(저장된 SQLite 텍스트) |
| `USER_SEQUENCES`, `ALL_SEQUENCES` | `SEQUENCE_NAME`, `MIN_VALUE`, `MAX_VALUE`, `INCREMENT_BY`, `CYCLE_FLAG`, `LAST_NUMBER` ... |
| `USER_INDEXES`, `ALL_INDEXES` | `INDEX_NAME`, `TABLE_OWNER`, `TABLE_NAME`, `UNIQUENESS` |
| `USER_TAB_COMMENTS`, `USER_COL_COMMENTS`, `ALL_*` | `COMMENT ON`의 내용 |
| `ALL_USERS`, `DBA_USERS`, `USER_USERS` | `USERNAME`, `USER_ID`, `ACCOUNT_STATUS`, `DEFAULT_TABLESPACE` ... |

- 뷰 정의는 Oracle SQL로 쓰여 있고, 프론트엔드가 FROM 자리에서 파싱해 넣습니다. 저장되는 것은 없습니다.
- `ALL_*`은 모든 사용자의 개체를 `OWNER`(시퀀스는 `SEQUENCE_OWNER`)와 함께, `USER_*`는 연결한 사용자 `MAIN`의 개체만 보여 줍니다. `DBA_*`(`DBA_TABLES` ...)는 `ALL_*`과 같습니다. 이름은 스키마를 뗀 이름입니다(`HR.EMP`가 아니라 `EMP`).
- 같은 이름의 테이블이 있으면 그 테이블이 먼저입니다. `SYS.USER_TABLES`처럼 `SYS`로 한정해도 됩니다.

## 타입 매핑

| Oracle | STRICT 저장 | 검사(이름이 Oracle 메시지인 CHECK) |
| --- | --- | --- |
| `NUMBER`, `NUMBER(p,s)`(s > 0), `FLOAT(b)`, `DECIMAL`, `REAL`, `DOUBLE PRECISION` | `ANY` | 숫자만(`ORA-01722: invalid number`), 정밀도(`ORA-01438`) |
| `NUMBER(p)`, `NUMBER(p,0)`(p ≤ 18), `INTEGER`/`INT`/`SMALLINT`(`NUMBER(*,0)`) | `INTEGER` | 정밀도 `abs(x) < 10^p` |
| `BINARY_FLOAT`, `BINARY_DOUBLE` | `REAL` | |
| `VARCHAR2(n [BYTE\|CHAR])`, `NVARCHAR2(n)`, `VARCHAR(n)` | `TEXT` | 길이 `octet_length(x) <= n`(CHAR 의미면 `length`) → `ORA-12899` |
| `CHAR(n)`, `NCHAR(n)` | `TEXT` + `COLLATE RTRIM` | 길이. 공백으로 채워 저장하고 공백을 무시하고 비교 |
| `CLOB`, `NCLOB`, `LONG` | `TEXT` | |
| `DATE`, `TIMESTAMP[(p)] [WITH [LOCAL] TIME ZONE]`, `INTERVAL ...` | `TEXT` | |
| `BLOB`, `RAW(n)`, `LONG RAW` | `BLOB` | `RAW(n)`은 길이 |
| `BOOLEAN`(23ai) | `INTEGER` | 0/1만 |
| `JSON`(23ai) | `TEXT` | `json_valid()`(`ORA-40441`). 저장 변환이 Oracle처럼 정규화한 JSON 텍스트를 넣음([JSON](#json)) |

- 선언 타입은 `xq_catalog`의 `type` 키에 Oracle 철자(`NUMBER(10,2)`, `VARCHAR2(20 CHAR)`, `NUMBER(*,0)`, `TIMESTAMP(6) WITH TIME ZONE`)로 남고, `xq_ora_coerce()`가 실행할 때 그 철자를 읽습니다.
- identity 열은 타입이 `NUMBER`여도 `INTEGER`로 저장합니다. 키이면 SQLite의 INTEGER PRIMARY KEY(rowid)입니다.
- sqlite3는 STRICT 타입과 CHECK를 그대로 강제합니다. 저장 변환(`xq_ora_coerce()`)은 이 방언의 DML에만 있습니다.

## 날짜

Oracle의 `DATE`는 시각을 포함합니다. 이 방언은 날짜를 SQLite 날짜 함수가 읽는 텍스트로 저장합니다.

- `DATE`: `'YYYY-MM-DD HH24:MI:SS'`
- `TIMESTAMP(p)`: `'YYYY-MM-DD HH24:MI:SS.ffffff'`(p자리 뒤는 0, 소수는 늘 6자리라서 텍스트로 비교됨)
- `SYSDATE`는 문장 시각(UTC)의 `strftime('%Y-%m-%d %H:%M:%S', 'now')`, `SYSTIMESTAMP`는 밀리초까지입니다.
- 질의 결과의 날짜도 이 텍스트입니다(`NLS_DATE_FORMAT`을 따르지 않음). `TO_CHAR(d, fmt)`로 형식을 정합니다.
- 날짜로 읽는 텍스트는 ISO 형식, 그리고 Oracle 기본 형식 `DD-MON-RR`(`DD-MON-YYYY`)입니다.

날짜 연산은 파서가 날짜라고 아는 피연산자에서만 날짜 연산이 됩니다(`dates.zig`). 날짜라고 아는 것은 `SYSDATE`·`SYSTIMESTAMP`, `TO_DATE`·`TO_TIMESTAMP`·`ADD_MONTHS`·`LAST_DAY`·`NEXT_DAY`·날짜의 `TRUNC`/`ROUND`, 날짜 상수, `CAST(... AS DATE)`, FROM에 있는 테이블의 `DATE`/`TIMESTAMP` 열, 그런 열 하나를 고르는 스칼라 서브쿼리, 그리고 날짜 연산의 결과입니다.

| Oracle | xqlite |
| --- | --- |
| `d + n`, `n + d` | `datetime(d, n \|\| ' days')`(밀리초 단위로 정확) |
| `d - n` | `datetime(d, (-n) \|\| ' days')` |
| `d1 - d2` | `(unixepoch(d1, 'subsec') - unixepoch(d2, 'subsec')) / 86400.0`(일 수) |

`TIMESTAMP`가 낀 연산도 `DATE`를 냅니다. `TIMESTAMP - TIMESTAMP`는 Oracle에서 `INTERVAL`이지만 여기서는 일 수입니다.

날짜 형식 모델(`TO_CHAR`, `TO_DATE`)은 `YYYY YYY YY Y RRRR RR SYYYY Q MM MON MONTH RM WW IW W DDD DD D DAY DY J HH HH12 HH24 MI SS SSSSS FF[1-9] AM PM A.M. P.M. FM`, `"텍스트"`, 구두점을 읽습니다. 이름은 영어(`AMERICAN`)이고 `Month`/`MONTH`/`month`의 대소문자를 따릅니다. `TO_DATE`는 Oracle처럼 구분자에 너그럽고, 빠진 연·월은 현재 연·월, 일은 1일입니다.

## 트랜잭션

Oracle에는 BEGIN이 없습니다. 트랜잭션은 첫 DML에서 시작해 `COMMIT`이나 `ROLLBACK`까지 갑니다. SQLite의 autocommit에는 이렇게 매핑합니다.

- INSERT·UPDATE·DELETE·MERGE·INSERT ALL은 autocommit 모드의 문장 하나로 실행되고, 끝에서 autocommit을 끕니다(`OP_AutoCommit 0`). 그래서 그 문장과 뒤의 변경이 열린 트랜잭션에 남습니다.
  - 이 코드는 실행할 때 `xq_ora_autocommit()`로 모드를 봅니다. 트랜잭션 밖에서 준비한 문장을 트랜잭션 안에서 실행해도(그 반대도) 맞게 동작합니다.
  - 실패한 DML은 그 문장만 되돌리고 트랜잭션을 열지 않습니다.
- `COMMIT`/`ROLLBACK`은 트랜잭션이 없으면 아무것도 하지 않습니다(SQLite는 오류).
- `SAVEPOINT`는 트랜잭션이 없으면 시작합니다.
- SELECT는 트랜잭션을 열지 않습니다.
- DDL은 Oracle과 달리 커밋하지 않습니다. 열린 트랜잭션 안의 DDL은 그 트랜잭션의 일부이고(SQLite의 DDL은 트랜잭션), 트랜잭션 밖의 DDL은 바로 커밋됩니다.
- 연결을 닫을 때 열린 트랜잭션은 되돌립니다(Oracle API와 같음, SQL*Plus는 종료할 때 커밋). xqlite 셸로 스크립트를 돌릴 때는 끝에 `COMMIT`을 쓰세요.
- DML의 `RETURNING`은 지원하지 않습니다. 이 꼬리 코드가 RETURNING 행보다 먼저 문장을 끝내기 때문이고, Oracle의 `RETURNING ... INTO`는 PL/SQL 구문이기도 합니다.

## MERGE와 INSERT ALL

`MERGE`는 같은 프로그램 안에서 문장 셋으로 내립니다.

```
MERGE INTO t USING s ON (c)
  WHEN MATCHED THEN UPDATE SET ... [WHERE u] [DELETE WHERE d]
  WHEN NOT MATCHED THEN INSERT (cols) VALUES (...) [WHERE i]
=>
UPDATE t SET ... FROM s WHERE c [AND u];
INSERT INTO t (cols) SELECT ... FROM s WHERE NOT EXISTS (SELECT 1 FROM t WHERE c) [AND i];
DELETE FROM t WHERE EXISTS (SELECT 1 FROM s WHERE c [AND u] AND d);
```

- 한 문장(한 VDBE 프로그램)이므로 함께 커밋되고 함께 실패합니다.
- ON 조건이 읽는 열을 UPDATE하면 Oracle처럼 `ORA-38104`입니다. 그래서 UPDATE 뒤에도 같은 행이 일치합니다.
- `DELETE WHERE`는 UPDATE 뒤의 값으로 판단합니다. INSERT 뒤에 실행해서 INSERT가 지울 행을 일치한 행으로 봅니다. 대신 INSERT가 넣은 행이 `DELETE WHERE`를 만족하면 그 행도 지워집니다(Oracle은 UPDATE한 행만 지움).
- 한 대상 행에 원본 행이 여럿 일치하면 Oracle은 `ORA-30926` 오류지만, 여기서는 SQLite의 UPDATE FROM처럼 그중 하나로 갱신합니다.
- UPDATE의 `WHERE u`는 DELETE에서 갱신된 값으로 다시 판단합니다.

`INSERT ALL`/`INSERT FIRST`는 INTO마다 `INSERT INTO ti (cols) SELECT values FROM (subquery) [WHERE ...]` 하나입니다. `INSERT FIRST`의 조건은 `CASE WHEN c1 THEN 1 WHEN c2 THEN 2 ... ELSE 0 END = k`입니다. 서브쿼리는 INTO마다 다시 실행되므로, 비결정적인 식(`SYSTIMESTAMP`는 문장 안에서 같음, `s.NEXTVAL`은 INTO마다 늘어남)은 Oracle과 다를 수 있습니다.

## JSON

Oracle Database 23ai의 JSON을 지원합니다. JSON 값은 텍스트이고, 경로 언어와 함수는 이 방언이 직접 구현합니다(`json.zig`). SQLite의 `json1`과는 문법(lax), 경로(`[*]`, 필터, 항목 메서드), 숫자와 출력 형식이 달라서 쓰지 않습니다.

### JSON 타입과 IS JSON

- `JSON` 열은 `TEXT`로 저장하고 `CHECK (json_valid(열))`을 붙입니다. 선언 타입 `JSON`은 `xq_catalog`에 남고 `USER_TAB_COLUMNS`는 `JSON`, 길이 8200입니다.
- INSERT·UPDATE가 넣는 값은 저장 변환(`xq_ora_coerce()`)이 Oracle처럼 바꿉니다.
  - lax 문법을 읽고, 압축 형식(공백 없음)으로 씁니다. `'{a : 1}'` → `{"a":1}`
  - 숫자는 Oracle `NUMBER`의 철자입니다. `1.50` → `1.5`, `1e2` → `100`, `-0.0` → `0`
  - 문법 오류는 `ORA-40441`, 중복 키는 `ORA-40444`
- 그래서 저장된 값은 RFC 8259 JSON이고, sqlite3도 `json_valid()` 검사와 `json_extract()`를 그대로 씁니다.
- `x IS [NOT] JSON [STRICT|LAX] [WITH UNIQUE KEYS] [DISALLOW SCALARS]`는 `xq_ora_is_json(x, flags)`입니다. NULL이면 NULL입니다. CHECK에 쓸 수 있습니다.
- lax 문법(기본): 따옴표 없는 키, 작은따옴표 문자열, 대소문자 무관한 `true`/`null`, `.5`·`+1`·`01`·`1.`·`0x10`·`NaN`, 끝의 쉼표, `/* */`·`//` 주석. `STRICT`는 RFC 8259입니다.

### 함수

| Oracle | xqlite | 지원 |
| --- | --- | --- |
| `JSON_VALUE` | `xq_ora_json_value()` | `RETURNING`(`VARCHAR2(n)`, `NUMBER(p,s)`, `DATE`, `TIMESTAMP`, `BOOLEAN`, `CLOB`, `JSON` ...), `TRUNCATE`, `ERROR`/`NULL`/`DEFAULT e ON ERROR`, `... ON EMPTY`(없으면 `ON ERROR`를 따름), `PASSING` |
| `JSON_QUERY` | `xq_ora_json_query()` | `WITH [CONDITIONAL\|UNCONDITIONAL] [ARRAY] WRAPPER`, `WITHOUT WRAPPER`, `PRETTY`, `ASCII`, `RETURNING`, `ERROR`/`NULL`/`EMPTY [ARRAY\|OBJECT] ON ERROR\|EMPTY`, `PASSING` |
| `JSON_EXISTS` | `xq_ora_json_exists()` | `PASSING e AS "v"`, `TRUE`/`FALSE`/`ERROR ON ERROR`. 조건(`WHERE`)으로도, 결과 열(23ai의 BOOLEAN)로도 |
| `JSON_OBJECT` | `xq_ora_json_object()` | `[KEY] k VALUE v`, `k : v`, `KEY k IS v`, 열 이름만(`JSON_OBJECT(k)`는 `{"k": ...}`, 쓴 대로의 이름), `*`, `FORMAT JSON`, `NULL`/`ABSENT ON NULL`, `RETURNING`, `STRICT`, `WITH UNIQUE KEYS` |
| `JSON_ARRAY` | `xq_ora_json_array()` | `FORMAT JSON`, `NULL`/`ABSENT ON NULL`(기본 `ABSENT`), `RETURNING` |
| `JSON_OBJECTAGG`, `JSON_ARRAYAGG` | 집계 `xq_ora_json_objectagg()`, `xq_ora_json_arrayagg()` | `ORDER BY`(배열), `NULL`/`ABSENT ON NULL`, `RETURNING`. 행이 없으면 NULL |
| `JSON_MERGEPATCH` | `xq_ora_json_mergepatch()` | RFC 7396, `PRETTY`, `ASCII`, `RETURNING`, `TRUNCATE`, `NULL`/`ERROR ON ERROR` |
| `JSON_SERIALIZE` | `xq_ora_json_serialize()` | `PRETTY`, `ASCII`, `ORDERED`, `TRUNCATE`, `RETURNING` |
| `JSON_TRANSFORM` | `xq_ora_json_transform()` | `SET`, `INSERT`(배열 위치 포함, 있으면 `ORA-40763`), `REPLACE`, `APPEND`, `REMOVE`, `RENAME`(맨 뒤로 옮김), `KEEP` |
| `JSON(x)`, `JSON_SCALAR(x)` | `xq_ora_json()`, `xq_ora_json_scalar()` | |
| `t.col.a.b[0].size()` | `xq_ora_json_dot()` | 점 표기([아래](#점-표기)) |
| `JSON_TABLE` | 테이블 함수 `xq_ora_json_table()` | [아래](#json_table) |

- 경로: `$`, `.key`, `."키"`, `.*`, `..key`(후손), `[n]`, `[n to m]`, `[n, m]`, `[last]`, `[last - n]`, `[*]`, 필터 `?(...)`(`== != < <= > >=`, `&&`, `\|\|`, `!`, `exists(...)`, `starts with`, `has substring`, `like`, `in (...)`, `@`, `$변수`), 항목 메서드(`size()`, `type()`, `length()`, `lower()`, `upper()`, `number()`, `string()`, `boolean()`, `abs()`, `ceiling()`, `floor()`, `double()`, `count()`, `sum()`, `avg()`, `min()`, `max()` ...). lax 모드입니다(배열의 멤버 접근은 원소마다, 스칼라의 `[0]`은 그 값).
- 경로는 문자열 상수여야 하고, 문장을 컴파일할 때 검사합니다. `$`로 시작하지 않거나 문법이 틀리면 `ORA-40597`, `lax`/`strict` 앞말은 Oracle 23ai처럼 `ORA-40442`입니다.
- 출력 형식은 SQL*Plus가 보여 주는 Oracle의 것입니다.
  - 압축 형식에는 공백이 없습니다(`{"a":1,"b":[1,2]}`).
  - `PRETTY`는 두 칸 들여쓰기, `"키" : 값`입니다. 컨테이너는 키 다음 줄에서 시작하고 빈 컨테이너는 여는 줄과 닫는 줄입니다.
  - 제어 문자는 `\u0001`, `ASCII`는 `é`입니다.
- 숫자
  - `JSON_VALUE`는 `NUMBER`의 철자입니다(`1e-2` → `0.01`).
  - `JSON_QUERY`와 다른 함수는 텍스트 문서의 철자를 지키고 지수 문자만 대문자로 씁니다(`1.50`, `1E2`).
  - SQL 숫자는 JSON에 `0.5`처럼 씁니다(Oracle의 `.5`가 아님).
- 오류 코드: `ORA-40441`(문법), `ORA-40456`(스칼라 아님), `ORA-40462`(값 없음), `ORA-40470`(값 여럿), `ORA-40480`(래퍼 필요), `ORA-40478`·`ORA-61723`(길이), `ORA-40473`(중복 키), `ORA-40629`(패치), `ORA-40762`·`ORA-40763`(`JSON_TRANSFORM`).
- JSON 결과에는 SQLite의 JSON 서브타입이 붙습니다. 그래서 `JSON_OBJECT('k' VALUE JSON_QUERY(...))`처럼 JSON 생성 함수에 준 JSON 결과는 문자열이 아니라 JSON입니다. 파서가 이렇게 바꾸는 값도 있습니다.
  - `JSON` 열은 `xq_ora_json(열)`로 감쌉니다.
  - 날짜는 ISO 8601 텍스트입니다(`replace(d, ' ', 'T')` → `"2024-01-02T00:00:00"`).
  - `TRUE`/`FALSE` 상수는 JSON의 `true`/`false`입니다.
- `JSON_VALUE`의 기본 결과는 `VARCHAR2(4000)` 텍스트입니다. 숫자 상수와 비교하면(`JSON_VALUE(d, '$.a') = 5`) Oracle처럼 숫자로 바꿔 비교합니다(`xq_ora_cast(..., 'NUMBER')`).
- `''`는 NULL입니다. `JSON_OBJECT('a' VALUE '')`는 `{"a":null}`이고 `JSON_VALUE('', ...)`는 NULL입니다.

### 점 표기

`t.col.a.b[0].c`, `t.col.a.size()`(테이블 별칭이 필요함)는 파싱 뒤에 FROM을 보고 정합니다. `t`가 FROM에 없으면 예전처럼 `스키마.테이블.열`입니다.

| 열 | 결과 |
| --- | --- |
| `JSON` 타입 | JSON 텍스트. 스칼라도 JSON(`"str"`, `true`, `null`) |
| 텍스트(`IS JSON` 검사가 있는 `VARCHAR2`·`CLOB`) | 스칼라는 SQL 값(`str`, `true`, JSON null은 NULL), 객체·배열은 JSON |

값이 여럿이면 배열로 감쌉니다. 항목 메서드로 끝나면 그 SQL 값입니다. 결과 열 이름은 첫 배열 단계 앞의 마지막 키(대문자)입니다.

### JSON_TABLE

`JSON_TABLE(doc [FORMAT JSON], '행 경로' [ERROR|NULL ON ERROR] COLUMNS (...)) [별칭]`은 엔진의 테이블 함수(eponymous 가상 테이블) `xq_ora_json_table(doc, spec)`입니다.

- `spec`은 파서가 쓰는 열 정의(JSON)입니다.
- 가상 테이블의 열은 `c0` ... `c99`이고, 파서가 JSON_TABLE 열의 참조(`jt.a`, 다른 테이블에 없는 `a`, `*`, `jt.*`)를 그 열로 바꿉니다. 결과 열 이름은 JSON_TABLE 열의 이름입니다.
- SQLite의 테이블 함수처럼 앞의 FROM 항목을 인자로 받습니다(`FROM t, JSON_TABLE(t.doc, ...) jt`, Oracle의 측면 조인).
- 상관 서브쿼리에서는 한정한 이름(`jt.a`)만 바꿉니다.

| 열 정의 | 뜻 |
| --- | --- |
| `name FOR ORDINALITY` | 그 단계의 행 번호(1부터) |
| `name [type] [TRUNCATE] [PATH 'p'] [... ON ERROR] [... ON EMPTY]` | `JSON_VALUE`. 타입이 없으면 `VARCHAR2(4000)`, 경로가 없으면 `'$.name'`(쓴 대로의 이름: `a`는 `$.a`, `A`는 `$.A`) |
| `name [type] FORMAT JSON [WITH ... WRAPPER] [PATH 'p']` | `JSON_QUERY` |
| `name [type] EXISTS [PATH 'p']` | `JSON_EXISTS`. 숫자 타입이면 1/0, 문자 타입이면 `'true'`/`'false'` |
| `NESTED [PATH] 'p' COLUMNS (...)` | 바깥 행마다 그 경로의 행(외부 조인: 없으면 NULL 한 행). 형제 `NESTED`는 Oracle처럼 합집합(다른 형제의 열은 NULL) |

`DEFAULT`는 상수만 됩니다(Oracle과 같음). 문서가 JSON이 아니면 행이 없습니다(`ERROR ON ERROR`면 `ORA-40441`).

### sqlite3에서

- `JSON` 열은 sqlite3가 그대로 읽고 씁니다. 검사는 `json_valid()`입니다. 다만 sqlite3가 넣는 값은 저장 변환을 거치지 않습니다(lax 문법은 거부되고, 숫자는 그대로).
- `IS JSON` 검사, 그리고 SQL/JSON 함수나 `JSON_TABLE`을 쓰는 뷰·생성 열은 `xq_ora_*` 엔진 함수를 부릅니다. 그래서 sqlite3에서는 그 테이블에 쓰거나 그 뷰를 읽을 수 없습니다(다른 방언 함수와 같은 한계). xqlite는 어느 방언의 연결이든 읽습니다.

## 사용자와 스키마

Oracle에서 스키마는 사용자입니다. 이 방언은 사용자를 공용 스키마 구현([방언 아키텍처의 스키마](architecture.md#스키마네임스페이스))에 올립니다.

- 연결한 사용자는 `MAIN`이고 그 스키마는 SQLite의 `main` 자체입니다. `USER`, `SYS_CONTEXT('USERENV', 'SESSION_USER')`, `USER_*` 뷰의 소유자, `ALL_*` 뷰의 `OWNER`가 `MAIN`입니다. 이름을 설정으로 바꾸지 않는 것은, 같은 파일을 어느 연결이 열어도 개체의 소유자가 같아야 하고 `main.t`·`MAIN.t`가 늘 같은 테이블이어야 하기 때문입니다.
- `CREATE USER u IDENTIFIED BY p`는 스키마 `U`를 목록에 올립니다. 그 개체는 main의 `"U.T"`라는 이름의 개체이고(인덱스 `"U.I"`, 시퀀스 `"U.S"`, identity 시퀀스 `"U.ISEQ$$_T_C"`), sqlite3도 `"U.T"`로 읽고 씁니다.

| 문장 | 하는 일 |
| --- | --- |
| `CREATE USER [IF NOT EXISTS] u IDENTIFIED ...` | 스키마 등록. 암호, `DEFAULT TABLESPACE`, `QUOTA`, `PROFILE`, `ACCOUNT` 같은 옵션은 무시. 이미 있거나 `MAIN`·`SYS`·`SYSTEM`·`PUBLIC`·붙인 데이터베이스 이름이면 `ORA-01920` |
| `DROP USER [IF EXISTS] u [CASCADE]` | 개체(테이블, 뷰, 시퀀스, 다른 사용자 테이블의 인덱스)와 함께 지움. 개체가 있는데 `CASCADE`가 없으면 `ORA-01922`, 없는 사용자는 `ORA-01918` |
| `ALTER USER u ...` | 사용자가 있는지만 검사(`ORA-01918`) |
| `GRANT`, `REVOKE` | 받아들이고 무시(모든 사용자가 모든 권한을 가진 것처럼 동작) |
| `CREATE SCHEMA AUTHORIZATION MAIN CREATE TABLE ... CREATE VIEW ... GRANT ...` | 연결한 사용자의 테이블·뷰를 한 문장(한 트랜잭션)으로 만듦. 다른 사용자 이름이면 `ORA-02421` |
| `ALTER SESSION SET CURRENT_SCHEMA = u` | 한정하지 않은 이름의 스키마. 실행할 때 바뀌고(없는 사용자면 `ORA-01435`), 준비된 문장은 다시 컴파일됨. `MAIN`으로 되돌림 |
| `SYS_CONTEXT('USERENV', p)` | `CURRENT_SCHEMA`는 현재 스키마, `CURRENT_USER`·`SESSION_USER`·`AUTHENTICATED_IDENTITY`는 `MAIN`, 모르는 매개변수는 `ORA-02003`. 다른 네임스페이스는 NULL |

`u.t`는 어디서나 됩니다: 질의·조인·서브쿼리, INSERT·UPDATE·DELETE·MERGE·TRUNCATE, `u.t.col`, `CREATE TABLE u.t`, `REFERENCES u.t`, `CREATE INDEX u.i ON u.t`, `CREATE VIEW u.v`, `CREATE SEQUENCE u.s`와 `u.s.NEXTVAL`, `ALTER TABLE u.t`, `DROP ... u.x`, `COMMENT ON TABLE u.t`.

- 이름 해석: `MAIN`(그리고 데이터 사전과 `DUAL`의 스키마 `SYS`)은 main, 붙인 데이터베이스 이름(`ATTACH`, `TEMP`)은 그 데이터베이스, 등록한 사용자는 main의 `"U.T"`입니다. 컴파일할 때 정하므로 뷰 텍스트에는 `"U.T" AS "T"`처럼 데이터베이스 이름 없이 남고, 별칭이 없는 FROM 항목·DML 대상은 원래 이름 `T`를 별칭으로 가져 `t.col`이 됩니다.
- 현재 스키마가 `U`이면 한정하지 않은 테이블·뷰·인덱스·시퀀스 이름과 DDL이 만드는 개체는 `U`의 것입니다. 단 WITH 질의 이름, 임시 테이블, `DUAL`(`U.DUAL`이 없으면)은 그대로입니다. `USER_*` 뷰는 Oracle처럼 현재 스키마와 상관없이 `MAIN`의 개체입니다.
- 없는 스키마의 오류는 Oracle과 같습니다: 질의·DML·DROP은 `ORA-00942`(시퀀스 `ORA-02289`, 인덱스 `ORA-01418`), `CREATE TABLE`·`CREATE INDEX`는 `ORA-01918`, `CREATE VIEW`·`CREATE SEQUENCE`는 `ORA-01917`.
- 한계: 이름 비교가 대소문자를 구분하지 않으므로 `"hr"`와 `HR`은 같은 사용자입니다. 다른 사용자 스키마의 전역 임시 테이블, 붙인 데이터베이스의 시퀀스, 동의어(`CREATE SYNONYM`)는 지원하지 않습니다. 권한은 검사하지 않습니다. `ALL_USERS.CREATED`는 NULL입니다.

## Oracle과 다른 점

| 주제 | Oracle | xqlite | 이유 |
| --- | --- | --- | --- |
| `NUMBER` | 38자리 십진수 | SQLite 수(64비트 정수 또는 실수). `0.1 + 0.2`는 `0.30000000000000004` | 저장 타입이 `ANY`/`INTEGER` |
| 숫자 출력 | `.5`, `2` | `0.5`, `2.0`(실수 나눗셈 결과) | sqlite3 API의 값 타입. `TO_CHAR`는 Oracle 철자 |
| 날짜 | `DATE` 타입, `NLS_DATE_FORMAT`으로 출력 | ISO 텍스트([날짜](#날짜)) | SQLite 날짜 함수가 그대로 읽음 |
| 날짜 연산 | 늘 타입으로 판단 | 파서가 날짜라고 아는 피연산자만 | 식의 타입은 이름 해석 뒤에야 알고, 아직 계산에 쓰지 않음 |
| 식의 타입 | | 수는 `NUMBER`(`BINARY_DOUBLE`이 섞이면 그것), 문자열 리터럴은 `CHAR(n)`, `\|\|`는 길이의 합인 `VARCHAR2`, `COUNT()`·`SUM()`·`LENGTH()`는 `NUMBER`, `TO_DATE()`는 `DATE`([코어의 타입](architecture.md#코어의-타입)). 결과 열의 선언 타입과 매개변수 타입에만 씀 | 타입은 메타데이터 |
| `SYSDATE` | 서버의 시간대 | UTC | |
| 0으로 나누기 | `ORA-01476` | 같음 | 64비트를 넘는 정수 결과는 오류가 아니라 실수(NUMBER는 38자리) |
| 이름의 대소문자 | `"Emp"`와 `EMP`는 다름 | 같음([이름의 대소문자](#이름의-대소문자)) | SQLite의 이름 비교 |
| `BOOLEAN`(23ai) | `TRUE`/`FALSE` | 정수 1/0. 셸과 서버는 `BOOLEAN` 열과 불리언 식을 `TRUE`/`FALSE`로 보여 줌([값 표시](architecture.md#값-표시)) | sqlite3 API로 돌아오는 값 타입 |
| 오류 문구 | ORA- 메시지 | 컴파일 때와 저장 변환의 오류, 실행 중 제약 위반([제약 위반](#제약-위반))은 ORA- 코드와 메시지 | |
| DDL | 앞뒤로 커밋 | 커밋하지 않음([트랜잭션](#트랜잭션)) | |
| `RETURNING` | `RETURNING ... INTO`(PL/SQL) | 지원하지 않음 | |
| 외래 키 | 늘 강제 | 같음. 이 방언의 첫 문장에서 연결의 `PRAGMA foreign_keys`를 켬. 응용이 끈 것은 그대로 둠 | sqlite3는 여전히 끈 채로 씀 |
| `CHAR` 비교 | 공백을 채워 비교 | `COLLATE RTRIM` | 근사 |
| 저장되는 식 | | IR이 SQLite 텍스트로 렌더링. 방언 함수는 `xq_oracle_substr(...)`처럼, 저장 변환은 쓰지 않음(DML에만) | 다른 방언에서도 같은 뜻. 단 sqlite3에서는 그런 식을 계산할 수 없음 |
| JSON 타입 | 이진(OSON) | 정규화한 JSON 텍스트 | sqlite3가 읽음 |
| JSON 결과 열의 순서 | `JSON_OBJECTAGG`, `ORDER BY` 없는 `JSON_ARRAYAGG`는 처리 순서 | SQLite가 행을 읽는 순서 | |
| 셸 | | 셸은 SQLite 규칙으로 문장을 나눔. `/` 줄과 `q'[it's]'` 같은 홀수 따옴표는 한 번에 넘긴 텍스트(`exec`)에서만 | 방언별 문장 경계는 아직 없음 |

### 제약 위반

이 방언으로 컴파일한 문장의 제약 위반은 Oracle의 코드와 메시지입니다. 제약은 `스키마.이름`으로 씁니다(main의 테이블이면 사용자 `MAIN`).

| 위반 | 메시지 | SQLSTATE |
| --- | --- | --- |
| PRIMARY KEY, UNIQUE, 유일 인덱스 | `ORA-00001: unique constraint (MAIN.T_PK) violated` | 23505 |
| `CREATE UNIQUE INDEX`가 중복을 찾음 | `ORA-01452: cannot CREATE UNIQUE INDEX; duplicate keys found` | 23505 |
| NOT NULL | `ORA-01400: cannot insert NULL into ("MAIN"."T"."A")`, UPDATE면 `ORA-01407: cannot update ("MAIN"."T"."A") to NULL` | 23502 |
| CHECK | `ORA-02290: check constraint (MAIN.T_CK) violated` | 23514 |
| 외래 키(자식 행) | `ORA-02291: integrity constraint (MAIN.T_FK) violated - parent key not found` | 23503 |
| 외래 키(부모 행) | `ORA-02292: integrity constraint (MAIN.T_FK) violated - child record found` | 23503 |

- Oracle은 이름 없는 제약을 데이터베이스의 번호로 `SYS_C0012345`처럼 부릅니다. 여기서는 고정된 이름 `SYS_C_<TABLE>_<COLUMNS>`(CHECK는 `SYS_C_<TABLE>`)입니다. 이름을 준 UNIQUE, PRIMARY KEY, FOREIGN KEY의 이름은 CREATE TABLE이 `xq_catalog`에 적어 둡니다(키 `constraint:<종류>:<열>`).
- 타입이 있는 열의 NOT NULL은 저장 변환(`xq_ora_coerce`)이 먼저 `ORA-01400`으로 막습니다. 그 오류는 SQL 함수의 오류라 결과 코드가 SQLITE_ERROR이고, UPDATE에서도 `ORA-01400`입니다.
- 문장이 끝날 때 찾는 외래 키 위반은 마지막으로 센 위반의 제약을 말합니다. 어느 제약인지 모를 때(지연 제약의 COMMIT, DROP TABLE)는 `ORA-02291: integrity constraint violated - parent key not found`입니다.

## 아직 하지 않은 것

| 영역 | 항목 |
| --- | --- |
| PL/SQL | `BEGIN ... END;`, `DECLARE`, 프로시저·함수·패키지·트리거·타입(`CREATE PROCEDURE` ...), `RETURNING ... INTO`, `SELECT ... INTO` |
| 쿼리 | `CONNECT BY` 계층 질의(`LEVEL`, `PRIOR`, `SYS_CONNECT_BY_PATH`), `PIVOT`/`UNPIVOT`, `MODEL`, `GROUPING SETS`/`ROLLUP`/`CUBE`, `KEEP (DENSE_RANK ...)`, `FETCH ... PERCENT`/`WITH TIES`, `SEARCH`/`CYCLE`, 플래시백(`AS OF`), `SAMPLE`, `LATERAL`/`CROSS APPLY` |
| 함수 | 정규식(`REGEXP_LIKE` ...), `INTERVAL` 상수와 연산, `AT TIME ZONE`, `NUMTODSINTERVAL`, `TO_CHAR`의 `TH`/`SP` 접미사, NLS 매개변수, `UPPER`/`LOWER`의 ASCII 밖 문자 |
| DML | `UPDATE t SET c = ROWNUM`, `LOG ERRORS`, `WHERE CURRENT OF` |
| DDL | `ALTER TABLE ... MODIFY`·`ADD CONSTRAINT`·`DROP CONSTRAINT`, 한 번에 여러 열 추가·삭제, `CREATE SYNONYM`, 구체화된 뷰, 파티션, `ORGANIZATION INDEX`, `ON COMMIT DELETE ROWS`(임시 테이블은 `PRESERVE ROWS`로 동작), `ALTER SEQUENCE`, 권한 검사(`GRANT`/`REVOKE`는 무시) |
| 트랜잭션 | DDL의 암묵적 커밋, 격리 수준 |
| JSON | `IS JSON (OBJECT\|ARRAY\|SCALAR)`, `strict` 경로 모드, `JSON_TRANSFORM`의 처리기(`IGNORE ON MISSING` ...)와 `NESTED PATH`·`CASE`·`SORT` 같은 연산, `JSON_TABLE`의 `TYPE(STRICT)`와 100개가 넘는 열, 경로의 `like_regex`·`eq_regex`와 날짜 비교, `JSON_ARRAY(서브쿼리)`, `JSON_OBJECT`의 비교식 값(`'k' VALUE a > b`), JSON 검색 인덱스, `JSON_DATAGUIDE`, `JSON_EQUAL`, JSON 관계형 이중성 뷰 |
| 오류 | 실행 중 오류의 ORA- 코드화, `ORA-30926`(MERGE의 중복 일치) |

## 검증

| 도구 | 하는 일 |
| --- | --- |
| `src/dialect/oracle/test.zig` | 종단 테스트(어휘, `''` 규칙, 질의, 날짜, DDL과 타입, identity·시퀀스, MERGE·INSERT ALL, 트랜잭션, 바인드 변수, 데이터 사전, JSON) |
| `xqt dialect-diff oracle` + `tools/dialect/oracle-cases.txt` | 실제 Oracle과 차등 비교. 61개 케이스(JSON 15개, 사용자·스키마 6개)가 Oracle Database 23ai Free와 같은 행·열 이름·오류 코드를 냄 |
| `xqt interop oracle` | sqlite3 교차 검증. 이 방언으로 쓴 데이터베이스(JSON 열 포함)가 sqlite3 무결성 검사를 통과하고, sqlite3와 xqlite(SQLite 방언)가 같은 행과 스키마를 읽어야 함 |
| `zig build fuzz -- ir_roundtrip` | 퍼저의 방언 목록에 Oracle이 있음. 다른 방언의 트리로 만든 뷰를 Oracle 프론트엔드로 읽고, Oracle의 훅으로 렌더링한 텍스트를 모든 방언에서 컴파일 |

차등 비교는 Oracle 컨테이너를 띄운 뒤 실행합니다(`$ORA_SQLPLUS`, 기본값 `podman exec -i xq-ora sqlplus -s -L xq/xqpass@FREEPDB1`). 케이스는 한 번에 하나씩 돌고, 각 케이스는 SYSTEM으로 XQ에 DBA 역할을 주고 이전 케이스가 남긴 사용자(`XQ_...`)를 지운 뒤, 사용자 XQ의 테이블·뷰·시퀀스를 지우고 날짜 형식을 이 방언의 것(`YYYY-MM-DD HH24:MI:SS`)으로 맞춘 뒤 시작합니다. 비교할 때 오류는 ORA- 코드로 맞추고(SQLite 문구의 제약 위반은 Oracle이 같은 경우에 내는 코드로), Oracle의 `.5`와 `TRUE`는 `0.5`와 `1`로 맞춥니다. 서버에 닿지 않으면 바로 실패하며 `zig build check`에는 들어 있지 않습니다. 둘 다 먼저 `zig build tools`가 필요합니다.

```sh
podman run -d --name xq-ora -e ORACLE_PASSWORD=xqpass -e APP_USER=xq -e APP_USER_PASSWORD=xqpass \
  gvenzl/oracle-free:23-slim-faststart
zig-out/bin/xqt dialect-diff oracle
zig-out/bin/xqt interop oracle
```
